# 스키마 정의 — 발화 JSONL · 평가 yaml · 코퍼스 메타

본 시스템이 *공통으로 읽고 쓰는* 데이터 구조 정의서.

각 정의의 *코드 진실원* 도 함께 명시 — 코드와 문서가 어긋나면 *코드가 진실*.

## 1. 발화 JSONL (`Sample`)

벤치마크 한 폴더 (`BENCHMARK/<bench_id>/`) 안의 `samples.jsonl`.

**한 줄 = 한 발화**. 평가 코드 / 학습 데이터 코드 모두 이 스키마로 읽음.

코드 진실원: [`../project/data/schema.py`](../project/data/schema.py) 의 `Sample` 클래스.

### 필수 7필드

| 필드 | 타입 | 의미 | 제약 |
|---|---|---|---|
| `key` | string | 전 데이터셋에서 발화 고유 식별자 | 비어 있으면 안 됨. 패턴: `<bench_id>_<6자리 idx>` |
| `audio` | string | wav 파일 경로 | **JSONL 기준 상대경로** (예: `audio/xxx.wav`). `load_samples()` 가 절대경로로 resolve |
| `duration_sec` | float | 발화 길이 (초) | `0.1 ~ 60.0` (그 외 검증 실패) |
| `text` | string | 원본 전사 | 공백/빈 문자열 X. 사람이 들리는 그대로 받아쓴 텍스트 |
| `text_normalized` | string | 정규화된 전사 | 공백/빈 문자열 X. `normalize_korean_asr(text)` 결과. **CER 계산 시 모델 출력과 비교되는 필드** |
| `corpus_id` | string | 어느 코퍼스 출신인지 | `data/Corpora_Meta_Table.xlsx` 의 `Title (U)` 와 일치 (FK) |
| `speaker_id` | string | 화자 식별자 | 학습/평가 화자 누수 방지에 필수. 미상이면 `unknown_<corpus>_<idx>` 부여 |

### 선택 3필드 (벤치마크 = 사실상 필수)

| 필드 | 타입 | 의미 | 허용 값 / 기본 |
|---|---|---|---|
| `age_group` | string | 화자 연령대 | 자유 문자열. 예: `"30대"`, `"70대"`, `"80대+"`. 기본 `"unknown"` |
| `gender` | string | 화자 성별 | `male` / `female` / `unknown`. 기본 `"unknown"` |
| `labeling` | string | 라벨 출처 | `human-review` (사람 검수) / `auto-stt` (자동 STT) / `raw` (원본 그대로). **벤치마크는 `human-review` 필수** |

### 검증 규칙 (자동 적용)

`validate_samples()` 호출 시 다음 8가지 검사:

| # | 규칙 | 위반 시 메시지 |
|:--:|---|---|
| 1 | 필수 7필드 존재 (값 `None` / `""` 도 안 됨) | `[line N] 필수 필드 누락: [...]` |
| 2 | `audio` 경로가 비어 있지 않음 | `[line N] audio 경로가 비어 있음` |
| 3 | `duration_sec ∈ [0.1, 60.0]` | `[line N] duration_sec 범위 밖` |
| 4 | `text` 공백/빈 아님 | `[line N] text 가 공백/빈 문자열` |
| 5 | `text_normalized` 공백/빈 아님 | `[line N] text_normalized 가 공백/빈 문자열` |
| 6 | `gender ∈ {male, female, unknown}` | `[line N] gender 값 잘못됨` |
| 7 | `labeling ∈ {human-review, auto-stt, raw}` | `[line N] labeling 값 잘못됨` |
| 8 | **(test 셋만)** `labeling == "human-review"` | `[line N] 벤치마크(test) 는 labeling='human-review' 필수` |
| 9 | **(선택)** train 화자와 무중첩 (`train_speakers` 인자 전달 시) | `화자 누수 감지: train 과 test 가 N명 겹침` |

호출 예:

```python
from project.data import load_samples, validate_samples

# 벤치마크 검증 (test 셋 추가 제약 적용)
samples = load_samples("BENCHMARK/Sample10_PracticeRef/samples.jsonl")
validate_samples(samples, for_test=True)

# 학습/평가 화자 누수 검증 (학습 데이터 있을 때만)
train_spk = {s.speaker_id for s in load_samples("data/GOLD/train.jsonl")}
validate_samples(samples, for_test=True, train_speakers=train_spk)
```

`load_samples()` 가 경로에 `/test/` 포함 여부로 `for_test` 자동 판단 (직접 지정도 가능).

### 실제 예시 (Sample10_PracticeRef 첫 줄)

```json
{
  "key": "Sample10_PracticeRef_000",
  "audio": "audio/5effb5f9704f492ee12557fd_16k.wav",
  "duration_sec": 13.653,
  "text": "15년을 키우던 강아지가 갑작스레 죽었잖아 그러니 다들 허망 하겠지 집안 자체가 지금 우울해.",
  "text_normalized": "15년을 키우던 강아지가 갑작스레 죽었잖아 그러니 다들 허망 하겠지 집안 자체가 지금 우울해",
  "corpus_id": "Sample10_PracticeRef",
  "speaker_id": "spk_5effb5f9704f",
  "age_group": "40대",
  "gender": "female",
  "labeling": "human-review"
}
```

전체 10건은 [`../BENCHMARK/Sample10_PracticeRef/samples.jsonl`](../BENCHMARK/Sample10_PracticeRef/samples.jsonl) — *작업 시 직접 열어 확인*.

### 입출력 함수

| 함수 | 시그니처 | 비고 |
|---|---|---|
| `load_samples(path, *, validate=True, for_test=None)` | `→ list[Sample]` | JSONL 로드 + 자동 검증. `for_test=None` 이면 경로의 `/test/` 로 판단 |
| `save_samples(samples, path)` | `→ int` | Sample 리스트 → JSONL. 부모 디렉토리 자동 생성. 줄 수 반환 |
| `validate_samples(samples, *, for_test=False, train_speakers=None)` | `→ list[Sample]` | dict 도 받음. Fail Fast |

모두 `project.data` 에서 import.

## 2. 평가 yaml (`BENCHMARK/configs/eval/<name>.yaml`)

[1_벤치마크구축.md TODO 3](1_벤치마크구축.md#todo-3-평가-yaml-설정--어떤-모델로--어떤-벤치마크-평가할지) 에서 작성하는 평가 설정 yaml.

코드 진실원: [`../project/evaluation/__init__.py`](../project/evaluation/__init__.py) 의 `evaluate_on_benchmark_suite()` + 각 어댑터의 `build_predict_fn()`.

### 최상위 키

| 키 | 타입 | 필수 | 의미 |
|---|---|:--:|---|
| `recognizer` | dict | ✅ | 인식기 설정 (모델 종류 + 경로 + 옵션) |
| `benchmarks` | list[string] | ✅ | 평가 대상 `bench_id` 목록. 각 항목 → `BENCHMARK/<bench_id>/samples.jsonl` 로 자동 lookup |
| `batch_size` | int | — | `evaluate_on_benchmark_suite` 의 배치 크기. 기본 16 |

### `recognizer` 키

| 키 | 타입 | 필수 | 의미 |
|---|---|:--:|---|
| `name` | string | ✅ | `BENCHMARK/results/<name>/` 폴더명. 모델 식별자 |
| `type` | string | ✅ | `whisper` / `sensevoice` — 어댑터 분기 |
| `model_path` | string | ✅ | 백본 경로 또는 학습된 `.pt` 체크포인트 |
| `backbone` | string | (Whisper) | Whisper 만 — processor 로드용 (`openai/whisper-small` 등). 체크포인트 평가 시에도 유지 |
| `options` | dict | — | 어댑터 `build_predict_fn()` 의 키워드 인자 |

### `recognizer.options` — Whisper

| 키 | 타입 | 기본 | 의미 |
|---|---|---|---|
| `language` | string | `ko` | 강제 decoder language 토큰 |
| `task` | string | `transcribe` | `transcribe` (그대로) / `translate` (영어로) |
| `beam_size` | int | 5 | 1 = greedy, 5 = 표준, 10+ = 정확하지만 느림 |
| `batch_size` | int | 16 | 추론 배치 크기 |
| `device` | string | `cuda:0` | GPU 인덱스 |

### `recognizer.options` — SenseVoice

| 키 | 타입 | 기본 | 의미 |
|---|---|---|---|
| `device` | string | `cuda:0` | GPU 인덱스 (그 외 옵션은 FunASR 내부 처리) |

### 예시

Whisper 백본 평가:

```yaml
recognizer:
  name: whisper_small_baseline
  type: whisper
  model_path: /data/FM/MODEL/whisper-small
  backbone: openai/whisper-small
  options:
    language: ko
    task: transcribe
    beam_size: 5
    batch_size: 16
    device: cuda:0

benchmarks:
  - Sample10_PracticeRef

batch_size: 16
```

SenseVoice 백본 평가:

```yaml
recognizer:
  name: sensevoice_small_baseline
  type: sensevoice
  model_path: /data/FM/MODEL/SenseVoiceSmall
  options:
    device: cuda:0

benchmarks:
  - Sample10_PracticeRef

batch_size: 16
```

학습된 체크포인트 평가 — `model_path` 만 변경:

```yaml
recognizer:
  name: whisper_finetuned_v1                 # 새 이름 (results 폴더 분리)
  type: whisper
  model_path: outputs/<exp>/model.pt.best    # ← 백본 → 체크포인트
  backbone: openai/whisper-small             # processor 는 그대로
  options:
    language: ko
    task: transcribe
    beam_size: 5
    batch_size: 16
    device: cuda:0

benchmarks:
  - Sample10_PracticeRef

batch_size: 16
```

실제 파일: [`../BENCHMARK/configs/eval/whisper_baseline.yaml`](../BENCHMARK/configs/eval/whisper_baseline.yaml), [`../BENCHMARK/configs/eval/sensevoice_baseline.yaml`](../BENCHMARK/configs/eval/sensevoice_baseline.yaml).

## 3. 평가 결과 파일

`evaluate_on_benchmark_suite()` 실행 후 `BENCHMARK/results/<recognizer.name>/` 아래 생성.

### `evaluation_report.txt` — 사람 읽기용

```
================================================================================
📊 ASR Evaluation Report — <recognizer.name>
   Date: <ISO 8601>
================================================================================

## 1. Benchmark Set Results (한국어 CER 표준)
--------------------------------------------------------------------------------
Benchmark                                  CER (%)   sCER (%)    Samples
--------------------------------------------------------------------------------
<bench_id>                                    <CER>     <sCER>     <N>
--------------------------------------------------------------------------------
Weighted Average                              <avg>                <total>
```

### `evaluation_report.json` — 자동 분석용

```json
{
  "model": "<recognizer.name>",
  "date": "<ISO 8601>",
  "meta": {},
  "benchmarks": {
    "<bench_id>": {
      "cer": <float>,         "scer": <float>,
      "wer": <float>,         "samples": <int>
    }
  }
}
```

### `<recognizer.name>_diff.txt` — 차이 발화만 (정성 분석)

```
# ASR Differences (<recognizer.name>)
# Total mismatches: <N>
# Date: <ISO 8601>
================================================================================
[<bench_id>_NNN] cer=<%>
  ref: <text_normalized>
  hyp: <prediction_normalized>
```

### `<bench_id>/predictions.jsonl` — 발화별 (정성)

각 줄에 *입력 Sample 의 모든 필드* + 다음 4개 추가:

| 추가 필드 | 의미 |
|---|---|
| `prediction_raw` | 모델 원시 출력 (특수 토큰 포함 가능) |
| `prediction_normalized` | 정규화 후 (CER 계산에 사용) |
| `benchmark_id` | 어느 벤치마크인지 |
| `model` | 어느 인식기인지 |

(`prediction` 필드는 후처리된 텍스트 — 어댑터 별 차이 흡수.)

## 4. 코퍼스 메타 (`CorpusMeta`)

`data/Corpora_Meta_Table.xlsx` 의 `RAW_통합` 시트 한 행에 해당. 코드로 다룰 때 `corpora.jsonl` 로 export 가능.

코드 진실원: [`../project/data/schema.py`](../project/data/schema.py) 의 `CorpusMeta` 클래스.

### 필드

| 필드 | 타입 | 필수 | 의미 |
|---|---|:--:|---|
| `corpus_id` | string | ✅ | FK 키. 메타시트 `Title (U)` 와 일치 |
| `title` | string | ✅ | 사람 읽는 이름 |
| `source` | string | — | `AIHub` / `HuggingFace` / `자체` 등. 기본 `"unknown"` |
| `domain_hint` | string | — | `general` / `command` / `medical` / `dialog` / ... 기본 `"unknown"` |
| `style` | string | — | `낭독` / `대화-자연발화` / `대화-격식` / `독백`. 기본 `"unknown"` |
| `language` | string | — | 기본 `"ko"` |
| `recording_env` | string | — | 기본 `"unknown"` |
| `license` | string | — | 기본 `"unknown"` |
| `version` | string | — | 기본 `"unknown"` |
| `url` | string | — | 기본 `""` |
| `speaker_note` | string | — | 화자 분포 메모 |
| `collected_at` | string | — | 수집 년월 (`yyyy-mm`) |
| `extra` | dict | — | 위에 없는 추가 컬럼은 모두 여기로 보존 |

> 컬럼별 *허용 값 카탈로그* 는 `data/Corpora_Meta_Table.xlsx` 의 `INFO` 시트가 진실원.

### 로드

```python
from project.data import load_corpus_meta

# 사전 변환된 corpora.jsonl 에서 로드
corpora = load_corpus_meta("data/GOLD/corpora.jsonl")
# {corpus_id: CorpusMeta}

print(corpora["AIHub_KorSpontSpeech"].license)
```

xlsx 직접 로드는 별도 스크립트 (`scripts/build_corpus_meta.py`) 가 담당 — xlsx → JSONL 변환.
