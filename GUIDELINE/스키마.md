# 스키마 정의 — 발화 JSONL · 평가 yaml · 코퍼스 메타

본 시스템이 *공통으로 읽고 쓰는* 데이터 구조 정의서.

각 정의의 *코드 진실원* 도 함께 명시 — 코드와 문서가 어긋나면 *코드가 진실*.

## 1. 발화 JSONL (`Sample`)

벤치마크 한 폴더 (`BENCHMARK/data/<bench_id>/`) 안의 `transcript.jsonl`.

**한 줄 = 한 발화**. 평가 코드 / 학습 데이터 코드 모두 이 스키마로 읽음.

코드 진실원: [`../project/data/schema.py`](../project/data/schema.py) 의 `Sample` 클래스.

### 필수 5필드

학습/평가가 **같은 스키마** 를 공유한다 (train/val/test 분기 없음).

| 필드 | 타입 | 의미 | 제약 |
|---|---|---|---|
| `key` | string | 전 데이터셋에서 발화 고유 식별자 | 비어 있으면 안 됨. 패턴: `<dataset_id>__<idx>` |
| `audio` | string | wav 파일 경로 | **JSONL 기준 상대경로** (예: `audio/xxx.wav`). `load_samples()` 가 절대경로로 resolve |
| `duration` | float | 발화 길이 (초) | `0.1 ~ 60.0` (그 외 검증 실패) |
| `text` | string | 원본 전사 (rich) | 키는 필수, **빈 문자열 `""` 허용**. 잡음·이벤트 정보 포함 가능 |
| `text_norm` | string | 정규화된 전사 | 키는 필수. **빈 문자열 `""` 허용** (잡음/이벤트만 있어 정규화 결과가 없는 발화). **학습 타겟 + CER 비교 필드**. 구두점(`? ! . ,`)은 유지 |

### 선택 2필드 (+ 자유 메타)

| 필드 | 타입 | 의미 | 허용 값 / 기본 |
|---|---|---|---|
| `age` | string | 화자 연령대 | `6세 이하` / `7-9세` / `10대` / `20대` … `90대 이상`. 기본 `"unknown"` |
| `gender` | string | 화자 성별 | `F` / `M` / `unknown`. 기본 `"unknown"` |

> 위 외의 추가 메타 키는 자유롭게 둘 수 있다(코드는 모르는 키를 무시).

### 검증 규칙 (자동 적용)

`validate_samples()` 호출 시 다음 6가지 검사:

| # | 규칙 | 위반 시 메시지 |
|:--:|---|---|
| 1 | 필수 5필드 키 존재 (`None` 불가). `key`/`audio`/`duration` 은 `""` 도 불가 (`text`/`text_norm` 은 `""` 허용) | `[line N] 필수 필드 누락: [...]` |
| 2 | `audio` 경로가 비어 있지 않음 | `[line N] audio 경로가 비어 있음` |
| 3 | `duration ∈ [0.1, 60.0]` | `[line N] duration 범위 밖` |
| 4 | `text` 키 존재 (값 `""` 허용) | `[line N] 필수 필드 누락: ['text']` |
| 5 | `text_norm` 키 존재 (값 `""` 는 허용 — 정규화 결과 없는 잡음 발화) | `[line N] 필수 필드 누락: ['text_norm']` |
| 6 | `gender ∈ {F, M, unknown}` | `[line N] gender 값 잘못됨` |

호출 예:

```python
from project.data import load_samples, validate_samples

samples = load_samples("BENCHMARK/data/Sample10_PracticeRef/transcript.jsonl")
validate_samples(samples)   # 학습/평가 공통 스키마 검증
```

### 실제 예시 (Sample10_PracticeRef 첫 줄)

```json
{
  "key": "Sample10_PracticeRef__000",
  "audio": "audio/5effb5f9704f492ee12557fd_16k.wav",
  "duration": 13.653,
  "text": "15년을 키우던 강아지가 갑작스레 죽었잖아 그러니 다들 허망 하겠지 집안 자체가 지금 우울해.",
  "text_norm": "15년을 키우던 강아지가 갑작스레 죽었잖아 그러니 다들 허망 하겠지 집안 자체가 지금 우울해.",
  "age": "40대",
  "gender": "F"
}
```

전체 10건은 [`../BENCHMARK/data/Sample10_PracticeRef/transcript.jsonl`](../BENCHMARK/data/Sample10_PracticeRef/transcript.jsonl) — *작업 시 직접 열어 확인*.

### 입출력 함수

| 함수 | 시그니처 | 비고 |
|---|---|---|
| `load_samples(path, *, validate=True)` | `→ list[Sample]` | JSONL 로드 + 자동 검증 |
| `save_samples(samples, path)` | `→ int` | Sample 리스트 → JSONL. 부모 디렉토리 자동 생성. 줄 수 반환 |
| `validate_samples(samples)` | `→ list[Sample]` | dict 도 받음. Fail Fast |

모두 `project.data` 에서 import.

## 2. 평가 yaml (`BENCHMARK/configs/eval/<name>.yaml`)

[1_벤치마크구축.md TODO 3](1_벤치마크구축.md#todo-3-평가-yaml-설정--어떤-모델로--어떤-벤치마크-평가할지) 에서 작성하는 평가 설정 yaml.

코드 진실원: [`../project/evaluation/__init__.py`](../project/evaluation/__init__.py) 의 `evaluate_on_benchmark_suite()` + 각 어댑터의 `build_predict_fn()`.

### 최상위 키

| 키 | 타입 | 필수 | 의미 |
|---|---|:--:|---|
| `recognizer` | dict | ✅ | 인식기 설정 (모델 종류 + 경로 + 옵션) |
| `benchmarks` | list[string] | ✅ | 평가 대상 `bench_id` 목록. 각 항목 → `BENCHMARK/data/<bench_id>/transcript.jsonl` 로 자동 lookup |
| `batch_size` | int | — | `evaluate_on_benchmark_suite` 의 배치 크기. 기본 16 |

### `recognizer` 키

| 키 | 타입 | 필수 | 의미 |
|---|---|:--:|---|
| `name` | string | ✅ | `BENCHMARK/results/<name>/` 폴더명. 모델 식별자 |
| `type` | string | ✅ | `whisper` / `sensevoice` — 어댑터 분기 |
| `model_path` | string | ✅ | 백본 경로 또는 학습된 `.pt` 체크포인트 |
| `backbone` | string | (Whisper) | Whisper 만 — processor 로드용 (`openai/whisper-small` 등). 체크포인트 평가 시에도 유지 |
| `options` | dict | — | 어댑터 `build_predict_fn()` 의 키워드 인자 |

### `recognizer.options` — Whisper

| 키 | 타입 | 기본 | 의미 |
|---|---|---|---|
| `language` | string | `ko` | 강제 decoder language 토큰 |
| `task` | string | `transcribe` | `transcribe` (그대로) / `translate` (영어로) |
| `beam_size` | int | 5 | 1 = greedy, 5 = 표준, 10+ = 정확하지만 느림 |
| `batch_size` | int | 16 | 추론 배치 크기 |
| `device` | string | `cuda:0` | GPU 인덱스 |

### `recognizer.options` — SenseVoice

| 키 | 타입 | 기본 | 의미 |
|---|---|---|---|
| `device` | string | `cuda:0` | GPU 인덱스 (그 외 옵션은 FunASR 내부 처리) |

### 예시

Whisper 백본 평가:

```yaml
recognizer:
  name: whisper_small_baseline
  type: whisper
  model_path: /data/FM/MODEL/whisper-small
  backbone: openai/whisper-small
  options:
    language: ko
    task: transcribe
    beam_size: 5
    batch_size: 16
    device: cuda:0

benchmarks:
  - Sample10_PracticeRef

batch_size: 16
```

SenseVoice 백본 평가:

```yaml
recognizer:
  name: sensevoice_small_baseline
  type: sensevoice
  model_path: /data/FM/MODEL/SenseVoiceSmall
  options:
    device: cuda:0

benchmarks:
  - Sample10_PracticeRef

batch_size: 16
```

학습된 체크포인트 평가 — `model_path` 만 변경:

```yaml
recognizer:
  name: whisper_finetuned_v1                 # 새 이름 (results 폴더 분리)
  type: whisper
  model_path: outputs/<exp>/model.pt.best    # ← 백본 → 체크포인트
  backbone: openai/whisper-small             # processor 는 그대로
  options:
    language: ko
    task: transcribe
    beam_size: 5
    batch_size: 16
    device: cuda:0

benchmarks:
  - Sample10_PracticeRef

batch_size: 16
```

실제 파일: [`../BENCHMARK/configs/eval/whisper_baseline.yaml`](../BENCHMARK/configs/eval/whisper_baseline.yaml), [`../BENCHMARK/configs/eval/sensevoice_baseline.yaml`](../BENCHMARK/configs/eval/sensevoice_baseline.yaml).

## 3. 평가 결과 파일

`evaluate_on_benchmark_suite()` 실행 후 `BENCHMARK/results/<recognizer.name>/` 아래 생성.

### `evaluation_report.txt` — 사람 읽기용

```
================================================================================
📊 ASR Evaluation Report — <recognizer.name>
   Date: <ISO 8601>
================================================================================

## 1. Benchmark Set Results (한국어 CER 표준)
--------------------------------------------------------------------------------
Benchmark                                  CER (%)   sCER (%)    Samples
--------------------------------------------------------------------------------
<bench_id>                                    <CER>     <sCER>     <N>
--------------------------------------------------------------------------------
Weighted Average                              <avg>                <total>
```

### `evaluation_report.json` — 자동 분석용

```json
{
  "model": "<recognizer.name>",
  "date": "<ISO 8601>",
  "meta": {},
  "benchmarks": {
    "<bench_id>": {
      "cer": <float>,         "scer": <float>,
      "wer": <float>,         "samples": <int>
    }
  }
}
```

### `<recognizer.name>_diff.txt` — 차이 발화만 (정성 분석)

```
# ASR Differences (<recognizer.name>)
# Total mismatches: <N>
# Date: <ISO 8601>
================================================================================
[<bench_id>_NNN] cer=<%>
  ref: <text_norm>
  hyp: <prediction_normalized>
```

### `<bench_id>/predictions.jsonl` — 발화별 (정성)

각 줄에 *입력 Sample 의 모든 필드* + 다음 4개 추가:

| 추가 필드 | 의미 |
|---|---|
| `prediction_raw` | 모델 원시 출력 (특수 토큰 포함 가능) |
| `prediction_normalized` | 정규화 후 (CER 계산에 사용) |
| `benchmark_id` | 어느 벤치마크인지 |
| `model` | 어느 인식기인지 |

(`prediction` 필드는 후처리된 텍스트 — 어댑터 별 차이 흡수.)
