학습 데이터로 모델을 파인튜닝하고 → [1번 벤치마크](1_벤치마크구축.md) 에 평가한다.

아키텍처마다 학습 방식이 달라 **별도 문서**로 나눠 둔다. 이 문서는 둘의 *공통 부분* 만 다룬다.

| 아키텍처 | 가이드 | 학습 방식 | 상태 |
|---|---|---|---|
| **Whisper** | [2_모델학습_whisper.md](2_모델학습_whisper.md) | HF `Seq2SeqTrainer` — 셀/CLI 에서 바로 학습 | ✅ 동작·검증됨 |
| **SenseVoice** | [2_모델학습_sensevoice.md](2_모델학습_sensevoice.md) | FunASR `train_ds.py` 를 `torchrun` 외부 프로세스로 | 🚧 명령 생성까지. end-to-end 미검증 |

## 큰 그림 (공통)

```
data/SILVER/train.jsonl                (학습 데이터 — Sample 스키마)
data/SILVER/val.jsonl                  (검증용 — 학습 중 모니터링)
        │
        │ ① 모델별 어댑터로 변환  (아키텍처별 문서)
        ▼
HuggingFace Dataset  /  FunASR JSONL
        │
        │ ② 학습 실행            (아키텍처별 문서)
        ▼
outputs/<exp>/                         (학습된 모델 + config.yaml + 로그)
        │
        │ ③ 1번 벤치마크에 평가   (아래 공통)
        ▼
BENCHMARK/results/<exp>/<bench>/{report, predictions, diff}
```

전처리(RAW→SILVER→GOLD)는 **독립적인 과정**이고, 학습은 그 결과물 JSONL **경로만 입력받는다**.

## 공통 config 구조

베이스는 [`../configs/default.yaml`](../configs/default.yaml). 복사 후 변경점만 수정한다.

```bash
cp configs/default.yaml configs/<exp>.yaml
```

두 아키텍처가 **공유하는 키** (모델별 키는 각 문서 참조):

```yaml
experiment:
  name: 20260619_exp1          # outputs/<name>/ 로 저장. W&B run name.
  seed: 42

paths:
  repo_root:   /home/cssong/workspace/TRAIN-ASR
  train_jsonl: ${paths.repo_root}/data/SILVER/train.jsonl
  val_jsonl:   ${paths.repo_root}/data/SILVER/val.jsonl
  outputs_dir: ${paths.repo_root}/outputs

data:
  text_field:  text_norm       # 학습 타겟 필드. 평가(CER 기준)와 일관되게 text_norm 권장.
  sample_rate: 16000
  max_label_len: 200
  num_workers: 4

training:
  epochs: 5
  batch_size: 8                # GPU 메모리에 맞춰. (SenseVoice 는 의미가 다름 — 해당 문서 참조)
  grad_accum_steps: 4
  lr: 1.0e-5                   # 파인튜닝 적정 1e-6 ~ 5e-5. 큰 LR 은 사전학습 손상.
  warmup_steps: 500
  precision: bf16              # A100/H100 → bf16, V100/RTX → fp16
  early_stopping_patience: 3

wandb:
  enabled: true
  project: train-asr
  group: null                  # whisper | sensevoice — W&B UI 분류용

runtime:
  cuda_visible_devices: "0"    # 쉼표 구분 GPU 인덱스 ("0" / "0,1" ...)
```

> 상단 주석에 **이번 실험에서 무엇을 왜 바꿨는지** 한 문장 박기 (나중에 결과 비교 시 필수).

## CLI 진입점 (공통)

권장 진입점은 런처 [`../scripts/train.sh`](../scripts/train.sh) 다.
config 의 `runtime.conda_env` / `runtime.cuda_visible_devices` 를 읽어 **해당 conda 환경 + GPU** 에서
[`../scripts/train.py`](../scripts/train.py) 를 실행한다 (python 은 자기 conda 환경을 못 바꾸므로 셸 런처가 담당).

```bash
# Whisper — HF Trainer 로 바로 학습
scripts/train.sh configs/<exp>.yaml whisper

# SenseVoice — torchrun 셸 명령만 출력 (별도 tmux 에서 실행)
scripts/train.sh configs/<exp>.yaml sensevoice

# GPU/env 덮어쓰기 (config 값보다 우선)
GPU=0 ENV=train-asr scripts/train.sh configs/<exp>.yaml whisper
```

> 인자 없이 `scripts/train.sh` 만 치면 기본값 `configs/default.yaml whisper`.

직접 python 으로 돌리려면 (conda 활성화·GPU 지정은 직접):

```bash
CUDA_VISIBLE_DEVICES=0 python scripts/train.py --config configs/<exp>.yaml --model whisper
```

`scripts/train.py` 는 config·시드 셋업 후 `--model` 로 분기하고, 실제 학습 로직 SoT 는
[`../project/training/run.py`](../project/training/run.py) (노트북도 같은 함수 호출).

> 장시간 학습은 **tmux** 권장 (노트북 커널/SSH 끊겨도 유지).

## 막힘 핸들 (공통)

| 증상 | 1차 조치 |
|---|---|
| CUDA OOM | `training.batch_size` ↓ → `grad_accum_steps` ↑, `precision: bf16` |
| 학습 너무 느림 | `data.num_workers` ↑, SSD 사용, `precision: bf16` |
| 중간에 멈춤 (재개) | 아키텍처별 재개 방식 — 각 문서 참조 |
| W&B 안 됨 | `WANDB_API_KEY` 확인, `wandb login` |
| `train.jsonl`/`val.jsonl` 없음 | 전처리 단계 산출물 — 본 가이드 범위 밖. [1_벤치마크구축.md](1_벤치마크구축.md)/전처리 문서 확인 |

## 자주 만나는 함정 (공통)

- **한 번에 여러 변수 바꾸기** → 어느 변경이 효과인지 모름. config 하나 = 변경점 하나.
- **기존 config 덮어쓰기** → 과거 결과와 매칭 깨짐. *새 파일* 로 분기.
- **학습 끝나고 평가 깜빡** → loss 만 보고 판단 금지. 위 평가 TODO 까지 한 묶음.
