# 1. 벤치마크 구축

평가용 벤치마크 1개 + 백본 모델로 CER 측정.

> **사전 조건**: `make setup` 완료, conda 환경 활성화, GPU 사용 가능 (`nvidia-smi`).

---

## 0. 작업 목적

- 음성인식기 학습 *전* 평가 기준 확보
- 기준 없음 → 모델 변경의 개선 여부 측정 불가
- 전체 평균 CER 1개 → 약점 가림

### 약점 가림 — 예시

| 모델 | 일반 | 노인 | 어린이 | 전체 평균 |
|---|:--:|:--:|:--:|:--:|
| A | 5% | 25% | 30% | 7% |

- 전체 7% 만 보면 노인/어린이 약점 안 보임
- 분해해서 보면 → "노인·어린이 데이터 보강" 같은 다음 행동 도출

### 벤치마크 = 축별 분할

| 축 | 예 |
|---|---|
| 도메인 | 카페주문 / 콜센터 / 강의 / 의료 / 일반 회화 |
| 화자군 | 노인 / 어린이 / 비원어민 / 일반 성인 |
| 환경 | 스튜디오 / 잡음 현장 / 전화 8kHz / 사투리 |

- 벤치마크 1개 = 한 축의 한 묶음
- 예: "노인 발화 1,000건", "전화 콜센터 1.5h"

## 1. 전체 구조

```
┌─ ① 메타 (엑셀 2개) ─────────────────────────────────────┐
│   data/Corpora_Meta_Table.xlsx                           │
│     └─ 오픈소스 코퍼스 카탈로그 (이미 정리됨)             │
│                                                           │
│   BENCHMARK/Benchmark_Meta_Table.xlsx                    │
│     └─ 벤치마크 정의 (이 작업에서 행 추가)                 │
└───────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─ ② 전처리 (노트북) ──────────────────────────────────────┐
│   원본 wav + 메타 CSV                                      │
│         ↓ 16kHz mono 변환 + 발화별 정규화                  │
│   BENCHMARK/<bench_id>/                                   │
│     ├── audio/*.wav                                       │
│     └── transcript.jsonl  (한 줄 = 한 발화, 7필드)           │
└───────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─ ③ 평가 (yaml + 명령) ───────────────────────────────────┐
│   BENCHMARK/configs/<name>.yaml                      │
│     ├─ 인식기 (백본 or 학습 체크포인트)                     │
│     └─ 타겟 벤치마크 목록                                  │
│         ↓ Python 셀에서 호출                               │
│   BENCHMARK/results/<model>/<bench>/                      │
│     ├── evaluation_report.txt   (정량 — CER 표)            │
│     ├── predictions.jsonl       (정성 — 발화별)            │
│     └── <model>_diff.txt        (정성 — 차이 발화)          │
└───────────────────────────────────────────────────────────┘
```

### 3부분 분리 이유

| 부분 | 변경 빈도 | 결과물 |
|---|---|---|
| ① 메타 | 낮음 (합의 후 고정) | 엑셀 행 |
| ② 전처리 | 코퍼스마다 1회 | wav + JSONL (캐시) |
| ③ 평가 | 모델/실험마다 (가장 자주) | 리포트 |

## 2. 두 메타시트 차이

### `data/Corpora_Meta_Table.xlsx` — *코퍼스* 카탈로그

| 시트 | 내용 |
|---|---|
| `RAW_통합` | 한 행 = 한 코퍼스. 예: AIHub KsponSpeech, Zeroth, FreeDialog |
| `INFO` | 컬럼 의미 + 허용 값 카탈로그 |

- 정보 단위: *코퍼스 자체* (라이선스, 출처, 화자 분포 등)

### `BENCHMARK/Benchmark_Meta_Table.xlsx` — *벤치마크* 카탈로그

| 시트 | 내용 |
|---|---|
| `BENCHMARKS` | 한 행 = 한 벤치마크. `Source Corpus` = `RAW_통합.Title (U)` (FK) |
| `INFO` | 컬럼 의미 + 허용 값 카탈로그 |
| `README` | 작성 규칙 |

- 정보 단위: *코퍼스에서 어떻게 추출했는지*
- 한 코퍼스 → 여러 벤치마크 가능

### 1코퍼스 → N벤치마크 예시

| 코퍼스 | 벤치마크들 |
|---|---|
| `AIHub_KorSpontSpeech` | `..._general_clean` / `..._general_other` / `..._general_noise` |

### 외래키 관계

```
Corpora.RAW_통합
  Title (U) = "AIHub_KorSpontSpeech"
                    │
                    │  FK
                    ▼
Benchmark.BENCHMARKS
  Source Corpus = "AIHub_KorSpontSpeech"
  Benchmark ID  = "AIHub_KorSpontSpeech_general_clean"
```

### 카탈로그 진실원

- 공통 컬럼 (Domain / Recording Env / License) 허용 값 → **Corpora INFO 가 진실**
- Benchmark INFO 와 불일치 → Corpora 기준 적용

## 3. 두 모델 공통 포맷 — 어댑터 패턴

### 문제

- 인식기 2종 (SenseVoice, Whisper)
- 포맷 다름 → 전처리 2배, 실수 2배

### 해결

```
transcript.jsonl  (공통 Sample 스키마)
   │
   ├──► Whisper 어댑터 (project/data/adapters/whisper.py)
   │      └─ HuggingFace processor 형식
   │
   └──► SenseVoice 어댑터 (project/data/adapters/sensevoice.py)
          └─ FunASR JSONL 형식
```

- 두 어댑터 추론 함수 시그니처 동일: `predict_fn(audio_paths) -> list[str]`
- 평가 코드 → 모델 종류 무관

### 효과

| 항목 | 결과 |
|---|---|
| 전처리 횟수 | 1회 → 2 모델 평가 가능 |
| yaml 구조 | 동일 (`type` 키 1개만 다름) |
| 결과 형식 | 동일 → 2 모델 비교 즉시 가능 |

### TODO 4. 평가 실행

#### 방법 A. CLI (권장)

```bash
# 기본 — GOLD 샘플셋(/data/ASR/BENCHMARK/SILVER/GOLD/<id>/transcript.jsonl)에서 평가
scripts/eval.sh BENCHMARK/configs/whisper_baseline.yaml

# 다른 데이터 경로 — 전량 SILVER / 로컬 샘플 등
scripts/eval.sh BENCHMARK/configs/whisper_baseline.yaml --bench-root /data/ASR/BENCHMARK/SILVER
scripts/eval.sh BENCHMARK/configs/whisper_baseline.yaml --bench-root BENCHMARK/data

# 빠른 확인 — 벤치마크별 10% 만 샘플링 (시드 고정, 재현 가능). 1.0=전량(기본)
scripts/eval.sh BENCHMARK/configs/whisper_baseline.yaml --sample-frac 0.1

# GPU 임시 변경 — yaml runtime.cuda_visible_devices 대신 이번 실행만 덮어쓰기
GPU=2 scripts/eval.sh BENCHMARK/configs/whisper_baseline.yaml
```

런처가 yaml 의 `runtime`(conda 환경·GPU)을 읽어 [`scripts/eval.py`](../scripts/eval.py) 를 실행한다.
GPU 는 평소엔 yaml `runtime.cuda_visible_devices` 로 정하고, 이번 실행만 바꾸려면 `GPU=N` 을 앞에 붙인다.
벤치 경로는 `--bench-root <루트>` 하나로 지정한다 (`<루트>/<bench_id>/transcript.jsonl`). 기본은 GOLD 샘플셋.

#### 결과는 어디에?

평가가 끝나면 **`BENCHMARK/results/<recognizer.name>__<타임스탬프>/`** 아래에 생긴다
(매 실행마다 타임스탬프가 붙어 따로 쌓임 — `--no-timestamp` 면 타임스탬프 없이 이름 그대로):

```
BENCHMARK/results/whisper_small_baseline__260623_153459/
├── evaluation_report.txt        # 사람용 요약 (CER/sCER, 슬라이스)
├── evaluation_report.json       # 기계용 동일 내용
├── <name>_diff.txt              # 정답 vs 예측 diff
└── <bench_id>/predictions.jsonl # 벤치마크별 발화 단위 예측 (분석용)
```

> `BENCHMARK/results/` 는 gitignore — 커밋되지 않는다.

> 학습 직후 자동 평가는 [2_모델학습.md](2_모델학습.md) 의 `EVAL_CONFIG` 참고.

#### 방법 B. Python (노트북 — `eval.py` 내부와 동일)

```python
import yaml
from pathlib import Path
from project.evaluation import evaluate_on_benchmark_suite

CFG = "BENCHMARK/configs/whisper_baseline.yaml"
cfg = yaml.safe_load(Path(CFG).read_text())
rec = cfg["recognizer"]

# 어댑터 분기 (yaml 의 type)
if rec["type"] == "whisper":
    from project.data.adapters.whisper import build_predict_fn
    predict_fn = build_predict_fn(
        rec["model_path"],
        backbone=rec.get("backbone"),   # 폴더 평가면 None — model_path 폴더에서 프로세서까지 로드
        **rec.get("options", {}),
    )
elif rec["type"] == "sensevoice":
    from project.data.adapters.sensevoice import build_predict_fn
    predict_fn = build_predict_fn(rec["model_path"], **rec.get("options", {}))
else:
    raise ValueError(f"unknown recognizer.type: {rec['type']}")

# 벤치마크 ID → JSONL 경로. 기본 GOLD 샘플셋 (전량은 .../SILVER)
ROOT = "/data/ASR/BENCHMARK/SILVER/GOLD"
benchmark_paths = {bid: f"{ROOT}/{bid}/transcript.jsonl" for bid in cfg["benchmarks"]}

evaluate_on_benchmark_suite(
    model_name=rec["name"],
    predict_fn=predict_fn,
    benchmark_paths=benchmark_paths,
    out_dir=f"BENCHMARK/results/{rec['name']}/",
    batch_size=cfg.get("batch_size", 16),
)
```

#### 내부 동작

1. 어댑터로 모델 로드 → `predict_fn` 생성
2. 각 벤치마크의 `transcript.jsonl` 로드 → audio 경로 추출
3. 배치 단위 추론 → 예측 텍스트
4. **양쪽 정규화** (`normalize_korean_asr`) 후 CER 계산
5. 슬라이스 평가 (`age`, `gender` 별 분해)
6. `BENCHMARK/results/<name>/` 에 리포트 저장

**`evaluation_report.json`** (자동 분석용 — 같은 내용 JSON)

### 정성 — `BENCHMARK/results/<model_name>/<bench_id>/`

**`predictions.jsonl`** (발화별):

- 입력 Sample 의 모든 필드
- + `prediction_raw` / `prediction_normalized` / `prediction` / `benchmark_id` / `model`
- pandas 로 임의 슬라이스 분석 가능

**`<model_name>_diff.txt`** (차이 발화만):

```
[Sample10_PracticeRef_005] cer=12.3%
  ref: 그래서 어디 가실 거예요
  hyp: 그래서 어디 가실거예요
```
